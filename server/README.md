# Habora — сервер

Хранит привычки, задачи и настройки каждого пользователя Telegram отдельно.

## Что нужно знать

**Регистрации нет.** Приложение открывается из Telegram, который передаёт
подписанные данные о пользователе. Сервер проверяет подпись токеном бота — и по
ней понимает, чьи данные отдавать. Паролей нет, восстанавливать нечего.

**Данные разделены.** Каждый запрос работает только со строками своего
пользователя. Чужую привычку нельзя ни увидеть, ни отметить.

## Запуск локально

```bash
npm install --prefix server
```

Скопируйте `.env.example` в `.env` и впишите токен бота из @BotFather:

```bash
BOT_TOKEN=1234567890:AA...
```

```bash
npm run dev --prefix server
```

## Переменные окружения

| Переменная | Зачем |
|---|---|
| `BOT_TOKEN` | Токен бота. Без него сервер не примет ни одного запроса |
| `PORT` | Порт. Хостинг обычно подставляет свой |
| `ALLOWED_ORIGIN` | Адрес фронтенда, например `https://habora-app.vercel.app` |
| `DB_PATH` | Файл базы. На хостинге должен лежать на постоянном диске |
| `ADMIN_ID` | Номер владельца в Telegram. Открывает команду `/люди` — список людей и блокировка. Не задана — команды нет |

## Важно при размещении на хостинге

База — файл SQLite. Если хостинг стирает файловую систему при перезапуске
(так делают многие бесплатные тарифы), данные пропадут. Нужен диск, который
переживает перезапуски, — на Render это Persistent Disk, на Railway — Volume.

## Закрыть кому-то доступ

Telegram запретить человеку писать боту не умеет — бан есть только у групп и
каналов. Отказывает сам сервер, по номеру Telegram: тот приходит подписанным
ключом бота, и подделать его нельзя.

**Один раз:** напишите боту `/id`, он ответит вашим номером. Впишите номер в
переменную `ADMIN_ID` на хостинге.

**Дальше:** команда `/люди` в чате с ботом. Он пришлёт список — имя, ник,
когда человек заходил последний раз — и кнопку напротив каждого:

- ⛔ — закрыть доступ
- ↩️ — вернуть

Список тут же перерисуется. Себя в списке нет: заблокировав себя, вы отрезали
бы себе и приложение, и эти самые команды.

Заперты обе двери: приложение отвечает такому человеку отказом (и стирает у
него сохранённую копию данных, чтобы не выглядеть работающим), а бот молчит —
«Старт» ничего не делает, кнопки не отвечают, напоминания и вести о напарниках
не приходят.

Если `ADMIN_ID` не задана, то же самое делается руками в базе:

```sql
SELECT user_id, first_name, username, last_seen, blocked FROM users;
UPDATE users SET blocked = 1 WHERE user_id = 123456789;
```

Через базу блокировка вступает в силу в течение минуты — столько сервер
держит список в памяти. Кнопкой в боте — сразу.

Данные человека остаются на месте, и из общих привычек он не пропадает —
иначе у его напарников исчезла бы половина истории. С нового аккаунта
Telegram он зайдёт снова: блокировка по номеру — порог, а не стена.
