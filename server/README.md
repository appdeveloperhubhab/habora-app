# Habora — сервер

Хранит привычки, задачи и настройки каждого пользователя Telegram отдельно.

## Что нужно знать

**Регистрации нет.** Приложение открывается из Telegram, который передаёт
подписанные данные о пользователе. Сервер проверяет подпись токеном бота — и по
ней понимает, чьи данные отдавать. Паролей нет, восстанавливать нечего.

**Данные разделены.** Каждый запрос работает только со строками своего
пользователя. Чужую привычку нельзя ни увидеть, ни отметить.

## Запуск локально

```bash
npm install --prefix server
```

Скопируйте `.env.example` в `.env` и впишите токен бота из @BotFather:

```bash
BOT_TOKEN=1234567890:AA...
```

```bash
npm run dev --prefix server
```

## Переменные окружения

| Переменная | Зачем |
|---|---|
| `BOT_TOKEN` | Токен бота. Без него сервер не примет ни одного запроса |
| `PORT` | Порт. Хостинг обычно подставляет свой |
| `ALLOWED_ORIGIN` | Адрес фронтенда, например `https://habora-app.vercel.app` |
| `DB_PATH` | Файл базы. На хостинге должен лежать на постоянном диске |

## Важно при размещении на хостинге

База — файл SQLite. Если хостинг стирает файловую систему при перезапуске
(так делают многие бесплатные тарифы), данные пропадут. Нужен диск, который
переживает перезапуски, — на Render это Persistent Disk, на Railway — Volume.
